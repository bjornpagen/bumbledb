## Multiple const-side connected Allen residuals could conjoin into one tighter overlap query for free — the driver takes only the first

missing-free-feature | medium | CONFIRMED | overlap-join-live
outcome: fixed ead48b79

### Summary

`overlap_enumerate` (crates/bumbledb/src/exec/run/overlap_leaf.rs:57-70) selects its pruning driver with a `find_map` over `allen_sources`: the FIRST residual pairing a cover-word interval against an outer-constant side under a connected mask (mask ⊆ INTERSECTS) wins, and only its `(q_start, q_end)` window feeds the one `query_into` call (:133-134). Any further const-side connected residuals on the same cover word are never consulted for the enumeration — they only re-filter the already-materialized candidate batch through the classify kernels (run_node.rs:273-347). But overlap conjunction against multiple constants is component-wise by the half-open law: `overlap(x,u) ∧ overlap(x,v) ⇔ x.start < min(u.end, v.end) ∧ x.end > max(u.start, v.start)` — exactly one `query_into(dir, max(starts), min(ends))` on the already-built index, with no new structure and no kernel change.

### Evidence (verified)

- **overlap_leaf.rs:57-70** — `let driver = allen_sources.iter().enumerate().find_map(|(r_idx, (lhs, rhs))| ...)`: matches `(Source::Batch(word), Source::Slot(slot))` in either orientation, gates on `mask.bits() & !AllenMask::INTERSECTS.bits() == 0`, and returns the first hit's `(word, bindings.get(slot), bindings.get(slot + 1))`. Remaining entries are never examined for the enumeration.
- **overlap_leaf.rs:133-134** — one `self.overlap.query_into(dir, q_start, q_end, &mut self.overlap_hits)` with the single driver's bounds.
- **interval/overlap.rs:160-176** — `query_into` computes `{i : start_i < q_end ∧ end_i > q_start}`: `starts.partition_point(|&start| start < q_end)` bounds the prefix, the max-end tree walk (`tree[node] <= q_start` prune, overlap.rs:52-63) reports within it. The two bounds are fully independent (the test-side naive twin at overlap.rs:263-271 is literally `start < q_end && q_start < end`), so a conjoined window needs zero changes to this module — including the degenerate `q_start ≥ q_end` case that arises when the constants are disjoint and only a spanning candidate satisfies both legs.
- **run_node.rs:273-347** — every Allen residual classifies the survivor batch: `(Batch, Slot)` and `(Slot, Batch)` shapes go through `allen_classify_const` (the latter under `mask.converse()`), then `allen_filter_batch` + `compact_u32_by_mask`. A second const-side leg therefore filters candidates that were already enumerated, materialized by `overlap_gather`, and tallied by `counters.batch` (run_node.rs:196).
- **The reachable shape** — bumbledb-bench/src/scenarios/rings.rs:193-207: `r2_temporal_ring` carries `intersects(var(4), var(5))`, `intersects(var(5), var(6))`, `intersects(var(6), var(4))` over the three hop spans. The node binding the last span (v6) receives two Allen residuals — `(v5, v6)` and `(v6, v4)` — both connected-mask, both const-side (v4, v5 outer-bound), both on the same cover word base for v6. Today's candidate set per outer row is the loosest single leg's; the conjunction is available for free. Baseline TALLY (bench-out/baseline-2026-07-25/TALLY.md) records r2 with join at ~100% of its 31.5ms wall.
- **The observable** — crates/bumbledb/src/exec/run/tests/intervals.rs:1080 (`the_overlap_enumeration_prunes_the_leaf_batch_to_true_candidates`) pins the leaf batch tally against a from-raw-rows candidate model; it is the natural home for the two-leg assertion.
- **Not already handled** — the index landed whole in commit be405715 (findings 012/048) with the single-`find_map` driver; no code path or doc records multi-leg conjunction.

### Failure scenario / impact

Not a correctness failure — a foregone pruning. An r2-shaped ring (or any leaf with ≥2 const-side connected Allen legs on one cover interval) where the legs are individually loose but jointly tight — `a intersects c` and `b intersects c` with `a` and `b` far apart — enumerates, materializes (`overlap_gather`), and kernel-classifies the union-sized single-leg candidate set per outer row, when the conjoined query would return the intersection-sized set from the same index at the same cost. The leaf batch tally scales with the loosest leg instead of the conjunction. Whether the path fires on the shipped r2 corpus additionally depends on group sizes clearing `OVERLAP_CROSSOVER` (=16) and suffix scannability, but the structural gap is unconditional.

### Suggested fix

Fold the driver `find_map` into a fold over ALL qualifying residuals — same `Batch(word)`, `Slot` other side, connected mask: `q_start = max` of the slot-side starts (`bindings.get(slot)`), `q_end = min` of the slot-side ends (`bindings.get(slot + 1)`). Residuals on a different cover interval word decline to the kernel filter exactly as today. The mask stays data and every residual still classifies the batch, so completeness is unchanged: each conjoined residual's mask ⊆ INTERSECTS means it individually rejects any tuple not overlapping its constant, so every withheld position is one some residual would have discarded — the module's existing completeness argument (overlap_leaf.rs:10-16), applied per leg. Extend `the_overlap_enumeration_prunes_the_leaf_batch_to_true_candidates` with a two-leg corpus (including a disjoint-constants case where only spanning intervals survive) asserting the conjoined candidate count.
