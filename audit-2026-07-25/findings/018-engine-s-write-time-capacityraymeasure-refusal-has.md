## Engine's write-time CapacityRayMeasure refusal has no verdict on the differential wall — both twins panic instead of comparing

incoherence | medium | CONFIRMED | lean-capacity-drift
outcome: fixed b0fa69f0

### Summary

The 0.8.0 capacity cutover (C17 slot law) moved the ray-measure refusal onto the write path: a Duration-weighed capacity edge needs a finite u64 in the value slot, so a ray child refuses typed at plan time (`Error::CapacityRayMeasure`). The differential wall cannot express this verdict on either side: `engine_write` maps only `CommitRejected` and `ClosedRelationWrite` and panics on every other engine error, and the naive model's `duration_measure` asserts on any ray reaching a Duration law — a comment that still calls it "a fixture bug" even though rays are honest values everywhere except closed-relation extensions. This is the exact no-arbiter state that stamped finding 024 documented for queries, whose R6 fix gave `enum Answers` a `MeasureOfRay` variant; `enum Verdict` never got the write-side equivalent.

### Evidence (verified)

- **Engine refusal is real and write-time**: `crates/bumbledb/src/storage/commit/plan.rs:222-226` — `plan_commit`'s Errors doc: "a ray-valued Duration weight has no finite u64 for the value slot, so it refuses typed at plan time"; the call at `plan.rs:449` (`child_weight`) reaches `interval_measure` in `crates/bumbledb/src/storage/commit/judgment.rs:164-182`, which returns `Err(Error::CapacityRayMeasure { statement, fact })` at `:176`.
- **Legal op against an accepted schema**: the engine's own tests drive it — `crates/bumbledb/src/storage/commit/tests/marks.rs:836-852` (`capacity_duration_weight_of_a_ray_refuses_typed`) and `:857-881` (the bound direction). Rays are refused only in closed-relation extensions (`crates/bumbledb/src/schema/validate.rs:1748-1764` — "Rays stay honest values everywhere else").
- **The wall, engine side**: `crates/bumbledb-bench/src/differential.rs:231-238` — `engine_write` matches `CommitRejected` and `ClosedRelationWrite`, then `Err(other) => panic!("engine refused a differential write: {other:?}")` at `:237`. `enum Verdict` (`:48-51`) is `Committed | Aborted(Vec<Violation>)` only.
- **The wall, naive side**: `crates/bumbledb-bench/src/naive.rs:718-727` — `duration_measure` asserts `!is_ray, "a ray has no finite measure (C10)"`; reached from both `child_weight` (`:695`, the weight) and `resolve_bound` (`:709`, the dependent bound). - **The query precedent that was never mirrored**: `differential.rs:73-80` — `enum Answers` carries `MeasureOfRay` (mapped at `:149`, `:165`, `:315`, `:354`), the finding-024/R6 fix. No write-side twin exists.
- **Absence confirmed**: `grep CapacityRayMeasure crates/bumbledb-bench/` — zero hits; the only engine-side non-test consumers are `verify_store/marks.rs:60` and `verify_store/facts.rs:291`.
- **Owed ruling recorded engine-side only**: `judgment.rs:103-106` — "a ray-valued Duration weight now refuses at WRITE time... visible only for a ray child under an absent parent" (OWNER RULING OWED).
- **Latent, consistent with green CI**: the conformance judgment fixtures (`crates/bumbledb-bench/src/conformance/judgment.rs`, e.g. `:933-961`) are handcrafted non-ray facts; theorygen mints rays on 1-in-4 interval draws (`crates/bumbledb-bench/src/corpus_gen/theorygen.rs:224-250`) but is validate-only, so no current lane pushes a ray child through a Duration-weight capacity write in the differential runner.

### Failure scenario / impact

Accepted schema: `capacity ROOM(id) <=[Duration(span)]{0..10} BOOKING(room)`. Op stream inserts a BOOKING with `span = [5, ∞)` — a fully legal write (marks.rs proves the engine handles it with a typed refusal). Engine side: `Error::CapacityRayMeasure` → `engine_write` panics "engine refused a differential write". Naive side: `judge` → `duration_measure` assert panics. The differential harness crashes on a legal op instead of reporting agreement or a readable divergence — and the semantic corner the engine explicitly flags as an owed owner ruling (ray child under an absent parent: engine refuses at plan time φ-gated but parent-blind, while the naive model has no parent group to sum) is precisely a case where the two sides could genuinely disagree, and the arbiter cannot see it. The same wall covers the bound direction (`resolve_bound` → same assert vs the engine's judge-time `CapacityRayMeasure` naming the target row).

### Suggested fix

Mirror the R6 precedent on the write side: add a `Verdict::RayRefused { statement }` (compared whole, typed identity — the direction-divergence lesson), map it from `Error::CapacityRayMeasure` in `engine_write` (and `engine_write_from`), and replace the naive asserts in `child_weight`/`resolve_bound`'s `duration_measure` path with the same typed refusal — pinning whichever semantics the owed owner ruling picks for the absent-parent corner (the naive model's answer there is the ruling made executable). Land it with a marks-style differential test: one ray child under a present parent and one under an absent parent, plus the ray-bound parent, asserting verdict parity or surfacing the divergence readably.
