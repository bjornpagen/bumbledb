# Event proposal — implementation baseline

**Revision 0.9.** The proposal extends public BumbleDB **v1.3.1** with a first-class
`event` field and owned `Event` value. Implementation has started: the owned core
and structural storage/binding and field/full dependency slices exist on
`codex/event-algebra`, along with checked finite maps and the structural relation
core, safe diagram inspection, finite information operations, indexed partitions
and sealed finite programs/fixed points, plus enabled actions, uniform one-step
permissions and fully observed strategy witnesses. Complete-binding Event/Test
query heads now support Boolean programs, ITE, fixed rosters and canonical
context-fault sets. Grouped Event Pack now preserves canonical group contexts,
empty values and participating provenance through scratch spill. BEDC v1 now
transports finite structural maps/roles and reconstructs their certificates at
import. Captured `use map` imports now expose pullback, all three images and
possible/guaranteed query heads with per-occurrence scope validation. Typed
`use faces`/`use product` imports now expose relation views, composition, residuals,
modalities and finite Star while retaining authored products/workspaces. Exact
fixed finite laws now retain zero-mass legal worlds, owned conditional observations
and canonical BEVT v2 persistence. Finite functions now support weighted images
and normalized conditional channels while preserving parent marginals. Fixed-law
conditioning, likelihood/Jeffrey revisions and signed host expectations now retain
mathematical receipts and explicit Event translations. Shared univariate source
families now retain exact domains, guard refinements, parameter-dependent signed
functions and normalized channels; conditioning, likelihood and Jeffrey updates
retain validity domains and zero-mass possibilities. BEVT v3 preserves family
Events, and BESC v2 reconstructs functions, channels, refinements, restrictions
and complete replayed receipts. Family SDK authoring/results, query observations,
multivariate solving and the remaining implementation gates are still open. The
complete proposal remains subject to explicit acceptance gates; it is not released.
The [native ledger](../docs/event-implementation.md) records what actually works.
The [package guide](PACKAGE.md) explains the committed source/evidence inventory
and verification from a fresh checkout.
The open-ended
representation research is closed. Its evidence and failed alternatives remain
preserved under the laboratory and archive.

An Event is a region of explicitly admissible worlds. Ordinary pointwise keys
and containments constrain those regions. Queries construct conditions,
relations, permissions and information bounds; a designated joint law supplies
probability observations. Empty Events remain values. Shared worlds and source
parameters remain shared through every operation.

The priority remains **native dependency-language fit, algebraic elegance, then
performance**. The initial general backend is a canonical completed function
with symbolic splits and essential-coordinate tables. Dense and packed carriers
remain independent semantic/performance controls. No universal speed ranking or
automatic adaptive backend is claimed.

## Verification

The reproducible commands and their evidence scope are in
[proof coverage](semantics/README.md). The current readiness audit checks the
active proposal, exact proof reports and retained semantic reference artifacts.
Production-source isolation belongs to the historical preimplementation audit;
it is not reasserted for a branch that now contains native Event code. Neither
readiness audit is a native performance qualification.

Revision 0.9 reconciles the plan with native progress and adds checked finite
fixed-point bounds and persistence-identity contracts. The exact revision 0.8
documents remain in [the baseline archive](archive/implementation-baseline-0.8/manifest.json).
Native pointwise field admission and contextual full projections now have
separate implementation and Lean evidence. The
[native map layer](../docs/event-maps.md) adds arbitrary Boolean readouts,
pullback, existential/universal image and a distinct surjectivity certificate.
The [native relation core](../docs/event-relations.md) adds full products,
membership-FD roles, shared-witness composition, residuals and graph/readout views.
The [finite program layer](../docs/event-fixed-points.md) now adds inspectable
typed programs, monotone admission, least/greatest iteration and Star. Its finite
certificate counts original legal worlds; continuous source presentations and
query compilation retain their separate acceptance gates.
The [finite partition helper](../docs/event-partitions.md) adds count rosters,
ordinary value grouping, same-world refinement and checked readout conversion.
It retains empty cells and keeps observable values in ordinary relation columns.
The [action layer](../docs/event-actions.md) adds explicit enabledness, greatest
inhabited permissions and ranked reachability/continuing-safety policies. Repeated
partial-observation play still needs adequate information/memory construction.
The [fixed finite source layer](../docs/event-sources.md) adds exact rational
density partitions, symbolic contraction and measured context identity.
[Finite functions/channels](../docs/event-functions.md) add exact weighted
images and conditional closure, with explicit outcome names and actor FD checks.
[Finite revisions and signed expectations](../docs/event-revisions.md) add explicit
conditioning, likelihood/Jeffrey updates and owned mathematical receipts. The
complete query algebra, parameterized sources, TypeSafe imports,
complete SDK authoring and integrated qualification remain the work specified
by the implementation plan.
