# Let the algebra's coordinate maps inform the layout

The layout experiment suggests a concrete constructor input: the coordinate
permutations expected by the relation algebra. This is a proposed layout-planning
rule, not an implemented automatic selector or a claim that locality alone picks
the fastest carrier.

For a set of checked bijections `P` on a fixed coordinate roster, build the
undirected graph containing an edge `c — p(c)` for each coordinate and map.
Its connected components are the orbits of the permutation group generated by
`P`. No enumeration of that group is needed. A coordinate set is preserved by
every map exactly when it is a union of these components.

The proof is short. A preserved set containing `c` contains every successive
image of `c` under the generators and their inverses. Because a finite bijection
has an inverse that is a power of itself, the undirected reachability formulation
has the same orbits. Conversely, each map sends every orbit to itself, so it
preserves any union of orbits.

In the XYZ relation fixture, all four maps rearrange whole faces while keeping
bit significance. The six orbits are therefore `{Xi, Yi, Zi}`, one per state
bit. This has immediate consequences before any timing result:

- A six-coordinate block can hold two complete orbits. Whole-face permutations
  then stay within the block and need no reordering of decision levels.
- An interleaved nine-coordinate packed tail can hold three whole orbits;
  a twelve-coordinate tail can hold four. An eight-coordinate tail cannot be a
  union of three-element orbits, so some required maps must cross its boundary.
- The paired-bit order's block boundaries still preserve orbits, but a terminal
  cut partway through a six-coordinate block may split an orbit. Sharing the
  same flat order does not make different leaf widths equivalent.

This predicts the availability of a local map kernel. It does not predict total
query speed: the same grouping can make partial existential elimination or
selector cross-products more expensive. The modal and full-relation lanes
measure those competing effects. The [packed map control](TAIL-MAPS.md) changes
the kernel while preserving the carrier and coordinate order.

An eventual `LayoutPlan` can retain the semantic coordinate roster, ordered
groups, coordinate-to-local-axis maps, and precompiled plans for common algebraic
maps and elimination sets. A plan needs exact facts such as `preserves_tail`,
`preserves_each_block`, or a general canonical rebuilding schedule. The published
Event handle stays the same size; these shared descriptors belong to its owner.

If an orbit is larger than the permitted block size, a bounded representation
cannot keep that orbit in one block. It must use the general transformation or
choose a different decomposition. This never removes converse, composition or
residuals from the algebra. It changes their execution plan and measured cost.
Checked cross-space lifting, nonbijective substitutions, source guards, and
changes of admissibility need richer plans than this finite permutation rule.

Packing whole orbits also leaves ordering choices inside and between groups.
Event structure, elimination sets, law factors, expected maps and construction
cost must be evaluated together. The current experiment seals a chosen layout
before import. Dynamic reordering, translation, persistent identity and the cost
of discovering a useful layout remain explicit work.
