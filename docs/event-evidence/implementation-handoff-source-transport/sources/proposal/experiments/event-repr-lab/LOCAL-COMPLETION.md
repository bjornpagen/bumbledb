# Candidate: preserve completion on untouched faces

This is the next hypothesis after dependency-directed gates. Eight Lean reports
now pass in the 129-report central suite, all eight without axioms. The Rust
strategies pass four shared differential suites and 110 native comparative
processes. The comparison retains 368 configurations and 1,472 matched pairs.
All 32 native ownership/symbolic acceptance processes and all four separate
graph-diagnostic processes pass.

An Event's completed predicate can couple X and Y arbitrarily. Nevertheless,
completion by independent idempotent face decoders makes it invariant under
each decoder separately:

```text
A(dx(x), dy(y)) = A(x,y)  implies  A(x,dy(y)) = A(x,y)
```

Existential or universal projection over X preserves that Y invariance when its
additional relation/gate depends on X alone. The result therefore needs completion
on X only. This removes repeated repair of an untouched face; it does not remove
that face from Event membership or assume that X and Y are independent events.

The current witness-gate policy removes gates on untouched faces, supplying this
premise. The joint and active policies can leave such a gate behind, in which
case local completion is unsafe. A coupled support also requires the general
path. Keep environments visible and complete their decoder coordinates; face
decoders are interpreted inside the resolved admitted environment.

The first conservative target completes every face containing any hidden
coordinate, plus the environment. Within this contract, compare source splits
in physical order with splits restricted to coordinates whose decoder actually
changes. Identity substitutions should not require new input cofactors, but the
comparison must isolate this traversal change from locality.

Partial completion is an internal construction view. Published Event roots must
still equal the ordinary full completion on every raw code. Intermediate
cofactors need not satisfy that public invariant. Their memo keys must include
the selected decoder-coordinate mask; reusing a full-completion cache entry for
an arbitrary partial cofactor can return the wrong function. All retained cache
capacity and intermediate nodes must be charged.

The checked [Lean statements](lean/LocalCompletion.lean) cover separate invariance,
existential/universal preservation, exact local completion, resolved-environment invariance, indexed local completion,
and counterexamples
to retaining an untouched support gate or using a coupled decoder. Rust will
still require independent finite, hidden-environment and cross-policy identity
checks. The native target remains the same 64 Events after actual Free Join.

## Independent controls

`EVENT_LAB_RETRACTION_COMPLETE=full|needed|local|local-needed` keeps gate policy
and ITE policy as separate dimensions. `full` remains the default.

| Strategy | Decoder coordinates | Source splits |
| --- | --- | --- |
| full | All nonidentity coordinates | Physical order |
| needed | All nonidentity coordinates | Only coordinates requiring substitution |
| local | Affected state faces plus environment | Physical order |
| local-needed | Affected state faces plus environment | Only coordinates requiring substitution |

Constructor and import normalization use the same full physical traversal in
all four strategies. Full-completion memo entries can be shared because the
result function is identical. Partial substitution has its own `(raw root,
selected decoder mask)` memo; identity substitutions are removed from that
mask. Reconstruction uses the existing conditional kernel, including for a
raw source coordinate whose decoder is not selected. A plain branch constructor
would be unsafe when a substituted decoder reintroduces an earlier coordinate.
Partial-map metadata, retained capacity and generated nodes are charged.

The resolved-environment theorem explicitly covers invalid/empty environment
codes: repair the environment, interpret each face decoder there, and use
separate invariance within that resolved environment. The environment remains
observed during existential quantification. The public root must equal full
completion on **all** raw codes. Arbitrary coupled support and hidden
environments fall back to the full decoder. Joint/active gate policies also
fall back because their remaining gates may constrain an untouched face.

## Measurement questions fixed before the native sweep

1. Does local completion reduce the fibred non-suffix query with all other
   policies fixed? Compare both physical orders and both decoder policies.
2. Does skipping identity/unselected source splits help independently? Keep all
   four strategies; compare `local` to `full`, `needed` to `full`, and
   `local-needed` to each of them. Traversal may change retained intermediates.
3. Do full-support and certified prefix suffix queries keep identical storage?
   Their existing direct paths bypass this new code and supply negative controls.
4. Do joint/active gates really select the conservative fallback? Their local
   and full versions should retain identical storage for a fixed traversal.
5. Does the effect survive the smaller local-table cutoff, original-support
   observation, canonical reimport and native owned/symbolic query acceptance?
6. Are the answers themselves changed in size? Run read-only root censuses in
   separate processes. Every strategy must produce the same canonical functions;
   graph reachability cannot be reported as reclaimed allocator memory.

Timed processes run serially, after compilation and correctness checking finish.
Matched controls use the same executable, input constructor and original legal
world oracle. Retain incomplete processes. Do not choose a winner from a faster
fragment that omitted count observation or failed canonical publication.

## Completed shared checks

Four suites pass under slab/enum storage, ITE/staged/equal conditional kernels,
and different selected completion defaults. Each suite exercises all three gate
policies and all four completion strategies in six decoder/cutoff combinations.
Each combination compares 196,608 product-domain operation results and 9,216
coupled-support results against independent legal-world partitions, including
every hidden-coordinate mask, empty environments, constants, random predicates
and partial-coordinate FDs. All strategies recover exactly the same canonical
root IDs. Another 65,536 pointwise checks per combination compare arbitrary
partial substitutions against direct simultaneous decoder evaluation, with cold
strategy memos, shared mask caches and complement checks. Existing role, count,
transport, large symbolic and source-law checks remain in the shared suite.

The four modes are experimental controls. A production implementation should
encode the admitted projection plan as data derived from owner certificates,
hidden coordinates and Event dependence. Its public API needs neither four
Event variants nor caller-selected repair policies. See the
[representation contract](../../representation.md#lower-certificates-to-operation-data).

## What this means for a Coup relation

As an algebraic illustration, let X be a whole legal state before an exchange
and Y a whole legal state afterward. The Event can require the exact card
conservation relationship between X and Y. It therefore couples the two states.
If a readout hides selected coordinates of X while retaining Y, the result can
still constrain Y in complicated ways. The theorem says that Y's encoding
already has its legal meaning; it need not be decoded a second time while
constructing this result. The hidden source witnesses and their relationship to
Y remain intact. The native readout fixture tests this mechanism on synthetic
legal-state domains; it is not a benchmark of a complete Coup exchange engine.
