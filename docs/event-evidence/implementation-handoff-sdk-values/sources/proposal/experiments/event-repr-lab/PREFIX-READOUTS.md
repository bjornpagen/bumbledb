# Information readouts after Free Join

The Rust workload now runs through native Free Join, and its shared core passes
both storage suites. The [native screen](READOUT-SCREEN.md) exposes both
the intended suffix-projection gain and severe general-fallback costs. The earlier
legal-relation program hides whole state faces. It can compare the
completed functions chosen by two decoders, but it cannot isolate the benefit
of prefix repair's additional partial-projection certificate.

The [frozen round audit](results/readout-final-audit.json) verifies 43 Rust source
files, 63 retained Python tools, the proof records, all comparisons and diagnostics,
and unchanged production sources. Capped processes remain explicit incomplete
evidence; the audit does not turn them into successful query measurements.

## Same mathematical query for every carrier

The workload uses actual three-input Free Join and grouped Event union. Its
inputs retain the same environment-indexed legal product as the relation lane.
For every complete binding it conjoins a transition predicate, an eligibility
predicate, and a target predicate. It unions those terms by group:

```text
E_g = union over complete bindings (r,t,q) in group g: r & t & q
```

The eligibility predicates use separate modular exclusions, so they do not
simply contain every transition predicate. For each grouped Event E, hide H
within X, Y, or both while retaining the environment. Publish:

```text
Possible_H(E)   = Exists_H(E)
Guaranteed_H(E) = !Exists_H(!E)
Ambiguous_H(E)  = Possible_H(E) & !Guaranteed_H(E)
```

E comes from the grouped input relations, before transitive closure: closure can
saturate these fixtures and turn a readout benchmark into a constant-result
benchmark. Retain E as a fourth output, giving 64 published Events for sixteen
groups and one mask per process. Measure the join/grouping and readout stages
separately. Compare several masks in separate, shuffled processes; changing a
mask changes the mathematical query, not just its implementation.

These are information readouts: a retained observation may permit E, force E,
or leave it unresolved. They are not sampled outcomes or probability thresholds.
A legal observation has at least its original world as a completion, so this
projection's fibres are nonempty. That fact does not remove the explicit
nonvacuity requirement for Must through an arbitrary transition relation.

A Coup interpretation is revealing some components of an otherwise hidden game
state, then asking whether a bluff is still possible or has become unavoidable.
The synthetic bit hierarchy tests the representation law. It does not establish
that an arbitrary Coup observation happens to be a prefix of this encoding.

A subsequent Coup fixture should place a chosen observer's known fields first,
then the hidden card fields, with deck legality inside the state domain. The
prefix construction theorem permits arbitrary finite domain constraints, so
that retained legal hand can have exactly its legal hidden-deal completions.
This does not infer independence between hands. Another observer's knowledge
may require a different readout order or the general exact projection path.
The current synthetic domain benchmark has not implemented that game fixture.

Those known fields must expose the player's roles, not internal physical-copy
handles. The [finite Coup reference](results/coup-fibre-reference.json) merges
78 internal Bob hands into fifteen role-hand observations while retaining all
4,290 underlying deals. Fourteen observations permit Cleo to hold a Duke;
Bob's two-Duke hand forbids it, and none forces it. The role fibres have different
populations, so uniformly counting fifteen role observations would change the
measure on deals. A role function that is not a prefix of the chosen encoding
needs an explicit checked readout or the general projection path; the decoder
cannot invent that encoding correspondence. This reference does not implement
the native information-readout lane.

That Coup reference conditions on Alice's fixed cards. Its Bob-hand projection
is a structural readout in that declared scope; it cannot be called Bob's actual
knowledge unless his admitted alternatives justify the same restriction.

## Oracle and useful countercontrols

Construct expected results outside timing by scanning original legal worlds,
recording membership/nonmembership by retained-coordinate value, then expanding
the resulting readout back over original support. Never enumerate completed raw
aliases as additional legal worlds. Check complete output bitsets, canonical
reimport, and the inequalities `Guaranteed <= E <= Possible`.

For nested hidden suffixes, Possible grows and Guaranteed shrinks. Equality
`Possible_H(E) = E` is the supported membership FD from the retained observation;
it is also equivalent to `Guaranteed_H(E) = E`. The prefix theorem supplies the
additional bridge to raw dependence for the new decoder.

Include three projection families:

- Low-bit suffixes, for which prefix repair has a direct construction proof.
- Whole faces, for which both factorwise decoders have that proof.
- Non-suffix masks, for which the prefix implementation deliberately falls back.

Within the suffix family, include a single hidden bit and half a face; use a
high bit as a same-cardinality non-suffix control. Apply masks to X and to both
X/Y. Keep each expected output and count separate, even if distinct groups
produce equal canonical roots. A later dedicated semantic check can establish
the nested-readout inequalities without enlarging every timed query.

Use bounded, holed and environment-dependent domains, both raw orders, and the
same physical stores/cutoffs. Retain the minimum decoder, anchored Essential,
packed and dense controls. Include full support as an identity-decoder control.

## Measurement boundary

Measure support/decoder construction, relation import, real join/grouping,
readout construction and exact original-support observation separately, as well
as complete fresh and warm totals. All requested result Events must be published;
a Boolean-only readout shortcut is a different query. Retain original support
and law coordinates even when a result ignores them.

This experiment asks whether the stronger projection law pays for a useful
information query. It does not select a probability law, establish arbitrary
semantic-field ordering, or settle event-aware planner pushdown. Its acceptance
must be separate from the whole-face native relation results.

`src/readout_bench.rs` now keeps construction, support setup, input import,
admission, bare join, grouping, readout construction and count observation
separate. Each of the two sizes and two outer-memo settings publishes 64 roots
per query. It records how many groups actually change under Possible and
Guaranteed, and how many readout outputs are nonconstant. Every timed fresh and
warm result is checked pointwise outside timing. Canonical reimport, the sandwich
inequalities and the readout membership FDs are checked in a separate clone,
so verification cannot enlarge the retained query owner.

The [slab](results/readout-slab-check.json) and
[enum](results/readout-enum-check.json) shared suites pass. Eight carriers each
check 824 finite queries, sixty nested-readout cases and two grouping boundaries.
These include holes, empty environments, hiding the environment, an irrelevant
scratch coordinate, and arbitrary copied support. Seven symbolic carriers check
two 61-coordinate cases against direct integer counts and exact expected roots.
On an odd-sized bounded domain, hiding the low bit leaves one unmatched even
state; the guaranteed even event is precisely that boundary state. No huge
world table is constructed for those checks.

The grouping boundaries are substantive. With two exhaustive alternatives A
and !A hidden by the readout, each is possible and their conjunction is
impossible. Neither is guaranteed separately, while their union is guaranteed.
Moving readout operators through the wrong connective loses shared witnesses
or changes the order of the quantifiers.

`readout_sweep.py` keeps masks as query dimensions, runs jobs serially, and uses
factored counting explicitly for completed-root carriers. Its collector compares
only identical domain/mask/face queries across carriers, count modes, stores and
physical orders. Different masks are different queries, even when their hidden
coordinate counts happen to match. The original-support joint count remains
available as an explicit control.

The [general information algebra](INFORMATION-ALGEBRA.md) is now proved in Lean
independently of any decoder. It identifies observable bounds, exact FD conditions
for moving filters, and the information order between observations. It justifies
future query-plan alternatives; the native workload here still reads out after
grouping.

medians with the outer memo are below; all values are milliseconds. Prefix uses

## The next fallback experiment has a precise algebraic target

The current general path clips to support, projects, then completes the result:

```text
b = normalize(Exists_H(S & a))
```

Here a is already a completed Event function, while S is the original legal
support. With decoder rho, the exact completed answer can instead be written:

```text
b(x) = exists v:
         S(v) & a(v) & agree_outside_H(v, rho(x))
```

This is one relation contraction with a functional graph. It keeps every
witness legal and shares that witness across all retained coordinates. On legal
x, rho fixes x, so it has exactly the desired information-readout meaning. On
raw aliases it depends only on rho(x), so it already has the completion
invariant. The expression applies to non-prefix observations too.

The next useful competitor is a fused projection/substitution kernel over that
expression, compared with the current staged implementation in one executable.
It may avoid large intermediate support predicates and repeated selector Apply,
but the equation alone does not prove that it will. Every subproblem must retain
the joint decoder selectors, original support and operand identity; treating
the selectors independently would lose their shared constraints. Local word
contraction and canonical publication should remain available beneath the same
interface.

Keep projection and canonical reimport as distinct experiments. The retained
minimum-decoder cap diagnostic reaches the limit inside the untimed reimport
clone's normalization. That is evidence of an import/verification cost, not
evidence that the timed query itself exhausted its owner. The successful
non-suffix queries independently expose costly timed normalization. A new
kernel must address each obligation without removing the checks or charging
verification residue to query memory.

There is a smaller same-representation control before implementing the full
fused contraction. `normalize` currently rebuilds a Shannon step as three
binary operations, `(low & !selector) | (high & selector)`, after completing
both cofactors. Those completed cofactors can coincide even when the original
ones differ. Returning the shared cofactor immediately, then comparing a direct
ternary ITE kernel with the three-operation form, can distinguish avoidable
normalization residue from inherent size of the completed answer. Neither
changes the decoder or resident Event meaning; neither gain is measured yet.

Acceptance should include the retained capped cases, suffix fast paths,
non-suffix masks, copied support and the 61-coordinate symbolic boundary.
Compare exact canonical roots, complete outputs, original-support counts,
temporary and retained nodes, construction and query phases. An adaptive
carrier switch remains a different proposal that must also pay conversion,
identity and law-contraction costs.

## Separate count experiment

The first prefix native screen makes original-support counting a substantial
part of the bit-major query. The [product-fibre count experiment](FACTOR-COUNTS.md)
now implements a way to use the legal product
and membership FD to remove entirely ignored state faces before contraction.
For an Event depending only on faces I and the retained environment:

```text
Count_S(E) = sum over legal environments e:
               |D(e)|^(3 - |I|) *
               count of tuples in D(e)^I satisfying E(e, tuple)
```

This follows from the cardinality of each omitted product fibre. It is an
integer count identity, not an inferred probability independence assumption.
The original domain and multiplicity remain essential; raw alias counts remain
wrong. The Rust implementation and four Lean reports now check this
specialization; a complete query can still have Events depending on all faces.

The native comparison measures it against the existing joint `(support, completed Event)` traversal
with identical roots and canonical storage. Charge any retained domain metadata
and execution-local caches. Keep the general path for arbitrary support, and
do not extend this count shortcut to a shared-parameter or correlated source
law without a separate pushforward/contraction proof. This is distinct from
both changing the Event representation and the partial-projection benchmark.

A concrete count specialization can inspect the completed root's exact physical
face mask. For each nonempty environment e, use the original environment selector
and domain predicates only for the participating faces. If a raw contraction
still includes all ambient coordinates, divide out exactly `2^(width * omitted)`
before multiplying by `|D(e)|^omitted`. The omitted coordinates are absent from
both operands, so that power-of-two factor is exact. Sum environments using their
original selectors, never the decoder selector extended to empty environments.

Partial-support roots are prepared immutably at construction. The count call
remains read-only; both count modes use identical resident roots/storage.
All-face Events and arbitrary-support owners retain the general contraction.
This count experiment does not exercise the additional partial-projection
certificate; the information-readout lane above remains a separate workload.
