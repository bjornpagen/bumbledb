# 30 — The TS aws4fetch store

Receipt box C, closed for real: the five verbs over S3-compatible
storage, `aws4fetch` (~4 KB SigV4 over platform `fetch`) as ruled in
proposals/40, no AWS SDK ever. Written AGAINST THE RENAMED SURFACE
(10 runs first).

## The verb mapping (each arm names its HTTP truth)

- `get` — GET; 404 ⇒ the absent arm; the etag is S3's ETag header
  VERBATIM (an opaque token — the store trait's etag is whatever the
  backend answers, compared only for equality; fsStore's computed
  blake3 and S3's MD5-ish ETag are both honest instances of one
  opaque-token contract, which the beauty pass's `Etag` brand states).
- `getIfChanged` — GET with `If-None-Match: <etag>`; 304 ⇒ unchanged.
- `putCreate` — PUT with `If-None-Match: *`; 412 ⇒ exists. (S3 general
  purpose supports this since Aug 2024; R2 and Express speak it too.)
- `putSwap` — PUT with `If-Match: <etag>`; 412 ⇒ moved.
- `delete` — DELETE, unconditional.

Ambiguous outcomes (timeout after the request may have landed) resolve
by the retry law the trait already documents: a follow-up GET
comparing content for create, re-reading the etag for swap; reads
retry with the jittered backoff constants the census pins.

## Scope

One constructor: endpoint, region, bucket, credentials (static keys or
a caller-supplied signer refresh), key prefix. ONE storage class —
`ckpt/*`, `log/*`, and the manifest all ride it; the dual-class split
(Express for `log/*`) is configuration that arrives with its measured
trigger, not now. Works against AWS S3 and R2 with the same signer;
the R2 wildcard-etag caveat from the vendor matrix gets a smoke case.

## The gated smoke

A credential-gated lane (`BUMBLEDB_S3_SMOKE_*` env; loud skip naming
the missing variables) that runs the store's conformance shapes against
a real bucket: create-only exclusivity racing two clients, CAS
linearization, the 304 poll, the GET-before-PUT negative-cache shape
the vendor matrix warns about, and one full replica/writer round-trip
(open, commit, reopen, restore). It runs in the execution session once
with real credentials, and forever after wherever the env exists.

## Also in this lane

The Rust `S3Store` smoke shares the same env contract so one bucket
proves both drivers; the cross-language interop lane gains an
s3-backed variant behind the same gate.
