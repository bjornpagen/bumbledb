# 00 — Program is the wrong model

A query in this engine is one head and a set of conjunctive rules. That is already Datalog's useful fragment: union of CQs, set semantics, the spanning seen-set as the only union. After this cut the meaning of a rule list is `mem_rulesAnswers`; the meaning of a Query is `evalQuery`. The rule loop is the implementation. Nothing about reachability required a second IR.

The Program cut took "one step past the fixpoint refusal" and built a **deductive-database object** beside the query: `Program { predicates, output }`, `PredId`, `AtomSource::Idb`, Tarjan SCC, a signature fixpoint, per-stratum `evalProgram`, fuel as a semantic parameter, `degenerate_embedding : Query → Program` so the query could pretend it had always been a one-predicate program. The engine then grew a second prepare/execute path (`validate_program`, `FixpointProgram`, k delta-variants, strata spans) whose job, in every cookbook sighting, is a **forest walk** plus optional folds over the finished set.

That is the wrong object for the product (`00-product.md`: the engine is never a rule-program runtime). Mutual recursion, nonlinear rules, interior predicates as a general IDB, chaotic signature sealing, `UnresolvedPredicateSignature`, `p(x) | p(x)` as a typable shape — all of it is generality the workload does not contain and the SQLite oracle already cannot express (`translate_program`'s gate: linear self-recursion, no mutual, no in-cycle fold). The Lean model paid for that generality in full: `Program` / `PAtom` / `stratumOp` / `finished` / `fueledLoop` / `evalProgram`, plus a coding transport so `evalRule` could be reused by punning `AtomSource` into `RelId`. Two atom types. Two evaluators. A theorem (`degenerate_embedding`) whose only job is to say the extra object is sometimes the old object.

**Elegance here** is the SQL-shaped fact the oracles already knew: a query may name views (`WITH`), evaluated once, in declaration order; it may name at most one recursive CTE, linear, base ∪ rec, set union; the main query reads finished tables and is the only place folds and measures live. Recursion is not a program. It is a **reach operator** whose least fixpoint is finite because heads project bound variables (`Countermodels.succ_prefixed_infinite` is the wall when they don't) and whose operator is monotone because the rec CTE contains no negation (`Countermodels.odd_not_monotone` is the wall when it does). The engine already has the loop: rules into one sink, watermark suffix as Δ, transient images, one delta occurrence per rec arm. Specialize that. Delete the rest.

Fuel is a resource bound, not a semantics. The denotation of reach is `lfpS reachOp`. `Error::FixpointBudgetExceeded` is honest incompleteness against that lfp, the same class as `ResultBytesOverflow` against `evalQuery` / `rulesAnswers`. Today's Lean `evalProgram` putting fuel in the public evaluator is the lie this cut withdraws.

Named heads in `query!` without a keyword were the sneak path: any named head lowered to `ir::Program`, so Program was the notation's default the moment a view appeared. The keyword is the fence. `with` / `with recursive` are unmissable. A named head without them is a compile error. Program cannot return through the macro.

The degenerate embedding dies with Program. A query with empty `views`/`with` and no rec is today's query **plus two empty fields**, by construction of `evalQuery_plain` — not by embedding into a one-predicate program and proving the embedding harmless. Lean spells the WITH list `views` (`with` is a keyword there); the engine field stays `with`.

Negation **inside** the rec CTE is refused (`NegationInRecCte`). That is not the same as anti-joining the finished rec from main, and it is not “inline the anti-join into main.” Filtering during the walk ≠ filtering after the lfp. Today's recursive predicate that anti-joins a lower stratum is a dropped shape. Today's non-recursive interior that reads a finished rec inlines into main — that *is* equivalent (the set is finished).

This is the culmination of the deletion work. Not a fence around Program. Deletion of Program.
