# 00 — Program is the wrong model

A query in this engine is one head and a set of conjunctive rules. That is already Datalog's useful fragment: union of CQs, set semantics, the spanning seen-set as the only union. After this cut the meaning of a rule list is `mem_rulesAnswers`; the meaning of a Query is `evalQuery`. The rule loop is the implementation. Nothing about reachability required a second IR.

The Program cut took "one step past the fixpoint refusal" and built a **deductive-database object** beside the query: `Program { predicates, output }`, `PredId`, `AtomSource::Idb`, Tarjan SCC, a signature fixpoint, per-stratum `evalProgram` dragging a strata witness through the denotation, `degenerate_embedding : Query → Program` so the query could pretend it had always been a one-predicate program. The engine then grew a second prepare/execute path (`validate_program`, `FixpointProgram`, k delta-variants, strata spans) whose job, in every cookbook sighting, is a **reachability walk** plus optional folds over the finished set.

That is the wrong object for the product (`00-product.md`: the engine is never a rule-program runtime). Mutual recursion, nonlinear rules, interior predicates as a general IDB, chaotic signature sealing, `UnresolvedPredicateSignature`, `p(x) | p(x)` as a typable shape — all of it is generality the workload does not contain. Program paid for that generality in full: `Program` / `PAtom` / `stratumOp` / `finished` / `fueledLoop` / `evalProgram`, plus a coding transport so `evalRule` could be reused by punning `AtomSource` into `RelId`. Two atom types. Two evaluators. A theorem (`degenerate_embedding`) whose only job is to say the extra object is sometimes the old object.

SQLite's inability to express mutual or nonlinear recursion is a **translator** fact (`translate_program`'s gate). Lean and the naive model already evaluate those shapes. Oracle inexpressibility is not a denotation reason, and it is not why this cut is linear. Do not specify the language by writing SQLite.

## The three knobs

`proposals/README.md` owns the table. This file records why each knob sits where it sits.

**Walls.** Range restriction on rec heads — creation quarantine restated — is why the lfp is finite (`reach_den_finite`; `Countermodels.succ_prefixed_infinite` is the wall when a head creates values). Negation or aggregation **through the cycle** — negating or folding the rec table itself — is why the operator would not be monotone (`reachOp_mono`; `Countermodels.odd_not_monotone` and `odd_no_fixpoint` are the walls). Those are complexity / well-foundedness facts, not product taste. The roster ban is wider than the wall — `NegationInRec` also refuses anti-joins of finished tables inside rec arms, which are monotone (today's `stratumOp_mono` proves exactly that stratified reading); that width is this-cut driver economy, filed OPEN, and no doc may cite monotonicity for it. The engine is not a Datalog runtime: no stored programs, no magic sets, no demand transformation, no internalization of the host loop. Fuel is a resource bound, not a semantics — the denotation of reach is `lfpS reachOp`; `Error::FixpointBudgetExceeded` is honest incompleteness against that lfp, the same class as `ResultBytesOverflow` against `evalQuery` / `rulesAnswers`. Today's Lean `evalProgram` has no fuel parameter — the loop computes its own sufficient fuel and `missingCount_le` proves the bound. The lie lives elsewhere: `40-execution.md` calls the evaluator “complete only under sufficient fuel” (false today), `fueledLoop` is public, and the denotation drags a strata witness (`programDen C p strat`). This cut withdraws all three: `reachDen` is `lfpS`, witness-free; `fueledLoop` becomes a private proof device; the docs sentence dies unreplaced. Recursion is never the answer: `evalQuery` is main `rulesAnswers` over a finished environment; empty main denotes `∅` even when `reachDen` is huge. The chain-window class (`w = w₁ ∩ w₂` in a rec head) stays OPEN — the head position is created, so it exits the finiteness theorem at its premise.

**This cut.** One recursive SCC, linear arms, one `ReachDriver`, interiors then rec then main. Linear is the right **algorithm** at this budget: each rec arm is one `DeltaVariant`, one Free Join plan; a new tuple walks one EDB edge; work tracks |E| · diameter (or |reachable| for a seeded forest). Nonlinear path-doubling (`P(x,z) ← P(x,y), P(y,z)`) is still semi-naive, still the same complexity class, and a **worse** graph algorithm here: k full FJ plans, and a round joins Δ against the accumulated closure, so work can go quadratic in the reachable set per round. Sighted graphs (org charts, primer DAGs) have small diameter; hop-by-hop wins. Primer's cycle detector is already this shape: linear `reach(from, to)` with extra EDB on the step arm, then main `reach(x,x)`. Cookbook 24/25 are the same family. One SCC is a prepare-family decision: one watermark, one TransientImage ping-pong. It is also how Tarjan and k-variant minting die with Program. It is not a claim that two sequential lfps are a different mathematics.

**OPEN.** Stacked sequential linear lfps (A finishes; B reads A as a finished set) are two least fixpoints, same class, two drivers — host two-prepares until a workload shows the extra prepare is the pain. Mutual-linear (one SCC, several names, each rule ≤1 rec atom) is the same class as self-rec with a bigger operator; even/odd encodes as one linear predicate with a parity column. Refusing it **in this cut** is how Program's multi-pred scratch / Tarjan cannot return. Packaging that refusal with Soufflé is sloppy. During-walk anti-join of finished tables in rec arms is the same honesty: monotone (the negated source is constant in the operator's argument), same class, refused this cut so the driver keeps one negation path — the trigger is a workload whose exclusion cannot be written positively. A named interior of a finished rec is inlining-equivalent; this cut inlines into main rather than growing a post-rec phase. Nonlinear stays refused until a measured L-scale query makes the linear encoding unnatural **and** `|Δ ⋈ Acc|` still fits 10 ms / `DEFAULT_FIXPOINT_TUPLES` (10⁷).

## What elegance is here

A query may name interiors (a DAG of CQs, evaluated once, in declaration order). This cut: at most one recursive SCC, linear, base ∪ rec, set union. The main query reads finished tables and is the only place folds and measures live. Recursion is not a program. It is a **reach operator** whose least fixpoint is finite because heads project bound variables and whose operator is monotone because the rec SCC contains no negation. The engine already has the loop: rules into one sink, watermark suffix as Δ, transient images, one delta occurrence per rec arm. Specialize that. Delete the rest.

Named heads in `query!` without a keyword were the sneak path: any named head lowered to `ir::Program`, so Program was the notation's default the moment a view appeared. The keyword is the fence. A named head without it is a compile error. Program cannot return through the macro. The tokens themselves are host sugar (`04-bindings-docs.md`); they are not `WITH RECURSIVE` as grammar law, and they are not how the IR is named. Lean and the engine spell the list `interiors`. (`with` is a Lean keyword. That collision was the tell.)

The degenerate embedding dies with Program. A query with empty `interiors` and no rec is today's query **plus two empty fields**, by construction of `evalQuery_plain` — not by embedding into a one-predicate program and proving the embedding harmless.

Negation **inside** the rec SCC is refused (`NegationInRec`). Name the two cases and stop conflating them. Negating the rec table itself — through the cycle — is the **wall**: the operator is not monotone (`odd_not_monotone`) and there is no fixpoint to mean (`odd_no_fixpoint`). Negating a **finished** table (EDB, an earlier interior) during the walk is monotone — `stratumOp_mono` proves exactly that stratified reading today — and is refused **this cut** so the driver keeps one negation path and `recLinear` stays one line; it is OPEN with a trigger (`05-cutover.md`). Neither case is “inline the anti-join into main”: filtering during the walk ≠ filtering after the lfp. Today's recursive predicate that anti-joins a lower stratum is a dropped shape — and the tree prices the drop at zero: no corpus case and no accepted test negates from inside a recursive rule. Today's non-recursive interior that reads a finished rec inlines into main — that *is* equivalent (the set is finished). This cut does not grow a post-rec interior phase; that is OPEN.

This is the culmination of the deletion work. Not a fence around Program. Deletion of Program.
