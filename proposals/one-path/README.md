# one-path — the post-audit deletion campaign

The PRD set for the bumbledb-log hardening pass. The audit that followed the
build produced a defect ledger; the owner's ruling on it produced this
directory: **no demotions, hard deletions, one way to do everything**. The
loser algebra's fast/slow duality dies whole — subsumption, republish, the
intersection, the W arithmetic, and the footprint wire section behind them —
leaving one loss path whose outcome is provably identical and measurably no
slower. The store protocol unifies to one on-disk dialect both languages
speak. Every knob that cannot express its advertised range dies. Every
bounded repair loop becomes unbounded with a legible scream.

These documents are **normative for this pass**: the numbered bumbledb-log
docs (proposals/00–90) remain the product's spec, and where this pass
changes the product, the pass's final act is amending those docs — this
directory describes the delta and then deletes itself. Where this set and a
numbered doc disagree during the pass, THIS SET wins, because it is the
owner's ruling on that exact disagreement.

Read [00-doctrine.md](00-doctrine.md) first — it is the razor every lane
cuts with. [10-one-path.md](10-one-path.md) is the centerpiece.
[90-rollout.md](90-rollout.md) is the dispatch.
