### C01/C03 addition (wave C) — canonical rejection evidence, exact symbols

`bumbledb::schema::evidence` (all `pub`; the log crate imports these
literally — nothing here depends on log types):

- `FAMILY: &[u8] = b"bumbledb.evidence.v1\0"`, `LAYOUT: u16 = 1` — the
  domain-separating frame header; strict decode refuses any other family/
  layout/kind. Physical bytes provisional until the F3 freeze (C12).
- `encode_violations(schema: &Schema, violations: &Violations,
  max_bytes: usize, work: &WorkContext) -> Result<Vec<u8>, EvidenceError>`
  — **the decide.rs entry.** Deterministic function of
  `(schema, violations, max_bytes)`: complete violated-statement set in
  strictly increasing StatementId order, per-violation kind tag,
  containment direction, exact widened u128 capacity measure, bounded
  examples as `(RelationId, canonical row bytes)`, and a per-violation
  `examples_truncated` label. Under the byte budget it drops EXAMPLES only
  (uniform rank across violations, deterministic) and labels the drop; if
  the example-free statement skeleton alone cannot fit, it refuses
  (`EvidenceError::Budget`) so the caller refuses BEFORE deciding.
- `encode_judged(schema, judged: &[JudgedViolation], max_bytes, work) ->
  Result<Vec<u8>, EvidenceError>` — same bytes from judge output directly
  (carries the judge's own truncation labels; used by tests/replay
  tooling). For an untruncated judgment `encode_violations` and
  `encode_judged` produce IDENTICAL bytes (authored test) — decide-time
  and replay-time evidence agree byte for byte, as `apply::materialize`'s
  exact comparison requires.
- `decode(bytes: &[u8], max_bytes: usize) -> Result<ViolationEvidence,
  EvidenceDecodeError>` — strict, schema-free frame decode (facts stay
  opaque canonical row bytes).
- `ViolationEvidence { violations(): &[EvidenceViolation] }` with
  `to_judged(&self, schema, work) -> Result<Box<[JudgedViolation]>,
  EvidenceInterpretError>` (exact judge round-trip) and
  `to_violations(&self, schema, work) -> Result<Violations,
  EvidenceInterpretError>` (the public rejection value, so decoded receipt
  evidence renders through the EXISTING `render_rejection` into the landed
  TS `Violation[]` spelling with no new vocabulary).
- `EvidenceViolation { statement: StatementId, kind: StatementKind,
  direction: Option<Direction>, measure: Option<u128>,
  examples: Box<[EvidenceFact]>, examples_truncated: bool }`,
  `EvidenceFact { relation: RelationId, fact: Box<[u8]> }`.
- Errors: `EvidenceError { Work, Row, Empty, Unordered, PointwiseConflict,
  ForeignStatement, ForeignRelation, Budget { needed, budget },
  LengthOverflow, Allocation }`; `EvidenceDecodeError { LimitExceeded,
  Family, Layout, Kind, Truncated, TrailingBytes, Tag, InvalidCount,
  Unordered, LengthOverflow, Allocation }`; `EvidenceInterpretError
  { Work, Row, ForeignStatement, KindMismatch, ForeignRelation,
  ForeignDirection }`.

  physical words for `Interval<F64>` — mirrors the F64 scalar's
  payload-vs-order-key split; chapter 11 requires both surfaces.

  enough for the reference path) over GATs to keep P02's adapter trivial.

  state the decision without hedging (wave C).**
- Last-violating-group capacity witness (one `JudgedViolation` per

  cited up to the example budget): **CONFIRMED by P00**; recorded in

  changing the witness rule after format freeze would change recorded

- Wave-C codec design choices: (a) evidence examples are spelled as
  `(RelationId, canonical row bytes)` — the one existing portable row
  codec, schema-checked at interpretation, so no second value vocabulary
  exists and forged bytes refuse through the same strict parser the store
  uses; (b) byte-budget truncation is uniform-rank across violations

  ordinary examples, and no landed producer emits Pointwise; (d) the
  result-record codec reuses the canonical row scalar tags verbatim so a
  cell means the same bytes in a fact, an evidence example and a declared
