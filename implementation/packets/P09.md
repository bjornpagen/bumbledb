## Wave-D closure changes (2026-09-05)

The P04R-recorded defect (P04.md hub request 2: `migration/hosted.rs` still
read/wrote remote HEAD bodies as BARE `encode_control`/`decode_control`
frames, so every migration CAS would frame-refuse against production heads)
is CLOSED. `migration/hosted.rs` now mirrors the landed `writer/hosted.rs`
grammar exactly:

- **Reads**: `HostedCutover::read_head` decodes the full composed
  `manifest::HeadRecord` (`manifest::decode_head`); authority logic runs on
  `record.control`. A bare control frame (or any malformed body) at a HEAD
  key is corruption-class (`MigrationError::Log(LogError::Corruption)`) —
  never silently accepted.
- **Transitions** (freeze/thaw/activate/delete): the successor body is
  composed onto the EXACT parent record with `HeadRecord::with_control` +
  `manifest::encode_head`, so `object_epoch`, the recovery root, named roots
  and GC state survive every cutover CAS; tombstoning a published target
  drops only the active recovery root (named roots/barrier progress kept,
  per the manifest grammar).
- **Target genesis**: `publish_target_genesis` publishes
  `manifest::genesis_head_body(frozen_target, target_object_epoch, cap)` —
  the same body `HostedHistory::create` publishes (genesis recovery root,
  empty roots, Idle GC). Lost-create resolution compares the decoded
  `record.control` against the expected authority (retention fields are the
  data plane's and do not decide the race).
- **Pre-genesis fence**: the cancellation tombstone is a composed
  `HeadRecord::cancelled_before_genesis(control, target_object_epoch)` body
  (no recovery root), CAS-created exactly as before.
- **Constructor**: `HostedCutover::new(store, source_prefix, target_prefix,
  target_object_epoch, limits)` — the new `target_object_epoch` is the
  initial open object epoch recorded in a target genesis or pre-genesis
  tombstone head (the same role as `HostedHistory::create`'s parameter); the
  SOURCE epoch is always read from its own composed head. Only
  `tests/migration_hosted.rs` constructed the driver; updated.
- **`executor.rs` is untouched**: its local attachment reads/writes
  (`integration_host_attachment` + bare `encode_control`/`decode_control`)
  are the CORRECT local projection (P04.md: "the local attachment remains
  the bare control projection").
- **Tests**: `tests/migration_hosted.rs` REWRITTEN onto the production
  `store::mem::MemStore` double (the private scripted `HostStore` twin is
  DELETED, mirroring P04R's writer_hosted.rs precedent; lost/dropped faults
  are `fail_next(Op::…, IndeterminateApplied/IndeterminateDropped)` script
  entries, with one dropped entry per bounded driver attempt for the
  "undeliverable" arms). All eleven prior scenarios are preserved; NEW
  coverage: `cutover_heads_are_composed_records_preserving_retention`
  (freeze/genesis/tombstone bodies decode through the manifest grammar with
  epoch/recovery/tail preserved), `named_roots_survive_every_cutover_transition`
  (retention a bare frame could not carry survives freeze AND thaw), and
  `a_bare_control_head_frame_refuses_as_corruption` (source freeze/thaw and
  target activation against 0.x bare frames). → MIG-05/09/14 hosted halves,
  the C08 composed-head seam, OPS-001.

### Identities and hash domains

| Role | Width | Producer | Domain |
| --- | --- | --- | --- |
| SchemaId | 32 | core v6 canonical schema stream, `bumbledb::schema::fingerprint::fingerprint` after `SchemaDescriptor::validate()` — exposed natively as `schema_file::schema_id` | core `bumbledb-schema-v6` label (P01-owned); NOT re-hashed by the log |
| PlanDigest | 32 | `migration::plan::plan_digest(&canonical_frame_bytes)` | `blake3::derive_key("bumbledb.migration.v1/plan-digest", frame)` |
| PrefixDigest | 32 | `migration::manifest` chain | `"bumbledb.migration.v1/prefix-digest"`; base = H(base-frame), step = H(prev_prefix ‖ entry-frame-without-own-prefix) — acyclic by construction |
| PlanSetDigest | 32 | `migration::manifest::plan_set_digest` | `"bumbledb.migration.v1/plan-set-digest"` over {starting prefix, source SchemaId, final target SchemaId, ordered suffix entry frames} |
| Application-state digest (`targetDigest`) | 32 | `migration::state::state_digest` | `"bumbledb.migration.v1/state-digest"` over the ordered canonical relation/row enumeration (excludes history/genesis — no self-reference) |
| Migration system digest (genesis preimage input) | 32 | `migration::history::system_digest` | `"bumbledb.migration.v1/system-digest"` over the framed history chain (inherited records + the new Applied record) |

Stable human labels (`id` in plan JSON, `StepLabel` natively) are 1..=64
bytes of `[a-z0-9-]`, unique per manifest, and are NEVER identity: matching
plans/operations is by digest. A different plan under a reused label is
drift; a frozen operation cannot be taken over by relabeling (MIG-07).
App-owned Id128 values are 16-byte application data, independent of every
32-byte digest above.

### Finite plan operation roster (opcodes)

A plan is `{ planVersion: 1, sequence, id, fromSchemaId, toSchemaId,
operations, destructive }`. Operations, in order:

| JSON `kind` | Native | Meaning |
| --- | --- | --- |
| `map-relation` | `Operation::MapRelation { source, target, fields }` | consume one ordinary source relation; produce one ordinary target relation. `fields` covers EVERY target field exactly once, in target field-declaration order, each `{ target: <field name>, expression: ScalarExpr }` |
| `empty-relation` | `Operation::EmptyRelation { target }` | produce one new ordinary target relation with no source counterpart |
| `drop-relation` | `Operation::DropRelation { source }` | explicitly consume (discard) one ordinary source relation; requires a matching `destructive` acknowledgement |
| `seed` | `Operation::Seed { target, rows }` | insert fixed canonical rows (explicit values, explicit IDs) into an already-produced target relation; deterministic, no generator/clock/network |
| `validate-schema` | `Operation::ValidateSchema { schema }` | the required complete-target-law judgment boundary; MUST be the final operation and MUST name `toSchemaId` |

Coverage is total over ORDINARY relations (closed relations are sealed
schema axioms, exempt and unnameable by data ops): every ordinary source
relation appears exactly once as `map-relation.source` or
`drop-relation.source`; every ordinary target relation exactly once as
`map-relation.target` or `empty-relation.target`. A source field whose
value no `fields` expression references is data loss and requires a
`destructive: [{relation, field}]` acknowledgement; dropped relations
require `{relation}`; stale acknowledgements refuse.

Expressions are the CORE `bumbledb::ScalarExpr` roster (C01/C05 — Var /
Literal / Negate / Add / Subtract / Multiply / Divide / Cast{ToF64,
ToF64Exact, ToI64Exact, ToU64Exact} / IsNaN / IsFinite), evaluated by the
core `ScalarEvaluator`. JSON spelling: `{"kind":"field","name":<source
field name>}`, `{"kind":"literal","value":<value>}`, `{"kind":"negate"|
"isNaN"|"isFinite","expr":E}`, `{"kind":"add"|"subtract"|"multiply"|
"divide","left":E,"right":E}`, `{"kind":"cast","cast":"toF64"|"toF64Exact"
|"toI64Exact"|"toU64Exact","expr":E}`. `Var` binds a SOURCE field by name;
whole-tree typing must equal the target field type (`ScalarExpr::
result_type`), no implicit promotion. There is no second evaluator, filter
DSL, callback, module path or executable text anywhere in a plan.

Value spelling is the one `schema_file` grammar (shared with schema
snapshots): `{"bool":true}`, `{"u64":"7"}`, `{"i64":"-7"}`,
`{"$f64":"<16 lowercase hex canonical bits>"}`, `{"id128":"<32 hex>"}`,
`{"string":"…"}`, `{"fixedBytes":"<hex>"}`, `{"intervalU64":["a","b"]}`,
`{"intervalI64":["a","b"]}`, `{"intervalF64":["<16hex>","<16hex>"]}`.
Fresh/generation spelling is DELETED and refused.

### Canonical plan frame (the hashed bytes)

`family "bumbledb.migration.v1\0" ‖ layout u16=1 ‖ kind u8` then fields,
big-endian, length-prefixed spans, no trailing bytes (mirrors the history
frame discipline). Kinds: 1=plan, 2=manifest base, 3=manifest entry,
4=plan-set, 5=state enumeration, 6=applied history record, 7=baseline
history record, 8=migration tombstone.

Plan (kind 1): `seq u64 ‖ label span ‖ from SchemaId 32 ‖ to SchemaId 32 ‖
op count u64 ‖ ops ‖ destructive count u64 ‖ destructive entries`. Ops:
tag u8 (0=map,1=empty,2=drop,3=seed,4=validate) + name spans + per-field
`target span ‖ expr` / row values. Expr tags: 0=var(name span),
1=literal(value), 2..=5 add/sub/mul/div, 6=negate, 7=cast(kind u8), 8=isNaN,
9=isFinite. Value tags mirror canonical wire kinds: 0 bool, 1 u64, 2 i64,
3 f64 bits, 4 string span, 5 fixedBytes span, 6 intervalU64, 7 intervalI64,
8 id128, 9 intervalF64 (two canonical bit words). JSON formatting can never
change a digest: digests hash THIS frame, produced from parsed data.

matches chapter 33's example): operations `[map-relation Note→Note {id:
field id, body: field body, pinned: literal false}, validate-schema <to>]`,
destructive `[]`. Frame bytes:

### Manifest and prefix chain

Manifest JSON: `{ "manifestVersion": 1, "planVersion": 1, "baseSchemaId":
hex32, "basePrefixDigest": hex32, "entries": [{ "sequence": "<dec>", "id",
"fromSchemaId", "toSchemaId", "planDigest", "prefixDigest" }] }`.
Base frame (kind 2): `manifest_version u16 ‖ plan_layout u16 ‖ base
SchemaId 32`; `basePrefixDigest = H_prefix(base frame)`. Entry frame
(kind 3): `seq u64 ‖ label span ‖ from 32 ‖ to 32 ‖ planDigest 32`
(EXCLUDES its own prefixDigest — self-exclusion); `prefix[i] =
H_prefix(prefix[i-1] ‖ entry_frame[i])`. Native verification: contiguous
`sequence` from 0, `from[0] = baseSchemaId` for a chain rooted at the empty
base, `from[i] = to[i-1]`, unique labels, every prefixDigest recomputed.
`planSetDigest` (kind 4) binds the starting prefix, the pending ordered
suffix and the source/final schema — a tenant path never enters any hash.

### Authoritative history records

Stored as host records in the authoritative LMDB (key `b'm' ‖ chain index
u64 BE`, transactional with facts/receipts/attachment; the receipt
namespace is `b'r' ‖ …` so retirement can never touch migration history).
Chain rules: at most one `Baseline`, only at index 0; `Applied` records
append contiguous manifest coverage.

```text
Applied {                                  (kind 6)
  operation: OperationId, plan_set_digest: [u8;32],
  source_database, source_incarnation: Id128 roles,
  source_schema: SchemaId, source_decision: DecisionStamp,
  source_state: StateStamp,
  target_incarnation: IncarnationId, target_schema: SchemaId,
  target_digest: [u8;32],
  steps: [{ seq, label, from_schema, to_schema, plan_digest }]
}
Baseline {                                 (kind 7)
  operation: OperationId, steps_through: u64,
  validated_prefix: [u8;32], target_schema: SchemaId,
  target_digest: [u8;32], reason: bounded utf8 span
}
```

Flattened `steps` across records (baseline contributes `steps_through`
positions) must equal the exact manifest prefix; recomputed prefix digests
must match. `target_digest` covers canonical application state only.
Initialization from the declared empty base executes the chain (including
seeds) and records one Applied over it; an empty-latest-schema shortcut
cannot mark skipped seeds Applied (there is no such entrypoint). Baseline
is a visibly different record with an explicit reason. Restore copies
records and adds provenance without rerunning seeds (P05 restore lane).

### Cutover states and native entrypoints

`migration::executor` (LocalHistory authority) and `migration::hosted`
(HeadAuthority transitions over the C07 `ConditionalStore`):

- `status(...)` read-only: `UpToDate | Pending | Drift | DatabaseAhead |
  FrozenForMigration | ReadyToSwitch | Activated | Aborted` + typed refusals.
- `migrate(env, request)` — verify manifest/plans/prefix → durable freeze
  under the caller-fixed `OperationId` + `FreezeIntent::Migration
  { plan_set_digest, target }` (stable ref before dispatch) → capture the
  frozen source position → ordered compiled-step evaluation with the CORE
  judge at every `validate-schema` boundary → ONE staged final target
  (core `InstanceBuilder::admit` complete admission + `Db::from_instance`
  publication into private staging) → genesis (`GenesisProvenance::
  Migration`) + inherited history + one `Applied` record + Frozen/
  AwaitingCutover control written atomically → durable no-overwrite install
  into the stable target namespace under its kernel lock, refusing the
  tombstone → `ReadyToSwitch { activation_ref }`. Still frozen.
- `activate(env, activation_ref)` — explicit; one-time authority
  transition; matching retry returns recorded evidence + CURRENT access
  mode, never thawing a later freeze or reviving deletion.
- `abort(env, request)` — durably fence the target FIRST (terminal
  tombstone in target control, or the pre-genesis tombstone under the same
  stable target-namespace lock / conditional head create), THEN thaw the
  matching frozen source. Uncertain cancellation (hosted Indeterminate)
  never authorizes thaw. Activation winning refuses automatic abort.
  A cancelled operation permanently reports Aborted.
- Ordinary open (`LocalHistory::open`, P04) never initializes or migrates;
  `status` performs no writes.

`ActivationRef = { operation, plan_set_digest, target: DatabaseIdentity,
target_genesis: DecisionDigest }` — returned before any activation attempt
and durable in the target control (freeze intent + genesis provenance).

Resume: same operation + same plan bytes only. A published verified target
is reused; unpublished work restarts from the fixed original source into
fresh staging; private scratch is never an applied prefix; conflicting
completed output for the same operation/source/plan refuses
(`MigrationOutputMismatch`), never overwrites.

## Implemented behavior

- `schema_file` — the ONE native schema grammar: strict `parse`,
  deterministic byte-stable `render` (`parse(render(d)) == d`), `schema_id`
  (core `validate()` + core v6 fingerprint), `fingerprint_hex`. The
  successor value/type arms (`id128`, `interval<f64>`, `fixedInterval`)
  parse; the old per-field `"generation"`/fresh spelling refuses loudly
  (`Shape("fresh generation is deleted")`) instead of being ignored.
  `fixedInterval<f64>` is unrepresentable and refuses.
- `migration::json` — one strict bounded JSON reader (objects/arrays/
  strings/u64/bool/null only; floats and bigints are never bare numbers)
  and one deterministic writer with the one canonical value spelling
  shared by schema snapshots, plan literals and seed rows.
- `migration::plan` — finite roster (`map-relation`, `empty-relation`,
  `drop-relation`, `seed`, `validate-schema`), core-`ScalarExpr`-shaped
  expressions spelled by source field name, canonical frame codec (the
  hashed identity), strict decode (unknown tags/prefix/trailing refuse),
  `parse_plan`/`render_plan` repo JSON boundary, bounded `[a-z0-9-]{1,64}`
  labels that are never identity. Unknown `planVersion` refuses before
  anything half-parses.
- `migration::manifest` — acyclic domain-separated prefix chain (base
  frame, per-entry self-excluding frames), complete `verify_manifest`
  recomputation (contiguity, schema chaining, unique labels, every prefix
  digest), `bind_plans` (plan bytes ↔ entry identity), `plan_set_digest`
  (starting prefix + source/final schema + ordered suffix; no tenant path
  in any hash), `append_entry` (the generation-side native helper P10
  calls), `parse_manifest`/`render_manifest`.
- `migration::compile` — the complete native plan admission: descriptors
  must fingerprint to the recorded SchemaIds, total source/target coverage
  over ordinary relations (closed relations are sealed axioms and
  unnameable), duplicate coverage refusal, seed shape/arity/order checks,
  exact expression typing through the core's own `result_type` (structural
  `value_matches` for direct copies/literals), unreferenced source fields
  and dropped relations require exactly-matching destructive
  acknowledgements (stale acks refuse), mandatory unique terminal
  `validate-schema` naming `toSchemaId`. Lowers onto `bumbledb::ScalarExpr`
  with `VarId(i)` = source field ordinal; no second evaluator exists.
- `migration::state` — work-charged private ordered-step state (canonical
  row bytes as set keys, linear `ByteReservation` charges, `work.rows`/
  `step` on every row), core `ScalarEvaluator` execution, and the CORE
  judge (`judge_final_state`) at EVERY `validate-schema` boundary — a later
  step cannot hide an earlier invalid intermediate state; `Rejected`
  carries the complete violation set and `Judge` failures are resource
  refusals, never shorter rejections. `digest()` is the canonical
  application-state digest (ordered relation/row enumeration, history/
  genesis excluded).
- `migration::history` — `Applied`/`Baseline` records under host key
  `b'm' ‖ index` (receipts are `b'r'`: retirement is structurally unable to
  erase migration history), codec with empty-steps and empty-reason
  refusals, `system_digest` over the framed chain (bound into the target
  genesis), `verify_chain` (baseline only at index 0 with recomputed
  prefix; flattened steps must equal the exact manifest prefix; ahead/
  branch/relabel refuse at position).
- `migration::lock` — the stable target namespace OUTSIDE staging:
  `<hex>.lock` kernel file lock (std `try_lock`, released by drop/process
  death, no expiry/takeover), `<hex>.tombstone` durable pre-genesis
  cancellation (create-new + fsync file and directory; idempotent for the
  matching authority, conflicting refuses; terminal, never removed),
  no-overwrite `install_target` that refuses the tombstone and an existing
  target, symlink refusal on every namespace path, `~stage/` private
  staging paths that are never adopted by name.
- `migration::executor` — `LocalMigration::{status, migrate, abort}` plus
  `activate_target`, `fence_target`, `initialize`:
  - `status` is read-only (verifies manifest, reads chain, reports
    UpToDate/Pending/Frozen + namespace observations); ordinary open
    (`LocalHistory::open`, P04) never initializes or migrates.
  - `migrate` verifies manifest → binds the exact pending suffix at the
    applied prefix → compiles the WHOLE suffix → resolves recorded target
    evidence BEFORE freezing (tombstone ⇒ permanent `Aborted`; published
    terminal/activated control ⇒ `Aborted`/`AlreadyActivated`/
    `TargetConflict` — a retry of a settled operation never thaws OR
    re-freezes anything) → durable freeze under the caller's stable
    `OperationId` + `FreezeIntent::Migration{plan_set_digest, target}`
    (matching op+intent is idempotent; matching op with different bytes is
    `PlanSetMismatch` — no takeover; foreign op is `SourceFrozenByOther`)
    → post-freeze tombstone re-check (an abort racing the freeze already
    holds its fence: stop frozen-and-resumable; the locked install would
    refuse the tombstone anyway) → live unactivated published target ⇒
    verified reuse under the held freeze: identity, frozen intent, chain
    extension, recomputed state digest, genesis seq 0 — conflicting
    completed output is `OutputMismatch`, never overwrite →
    captures the frozen source in one coherent read → ordered execution →
    ONE final target through the core `InstanceBuilder` complete admission
    (`AdmissionRejected` carries the full violation set) → genesis
    (`GenesisProvenance::Migration`) + inherited chain + ONE `Applied`
    record + `Frozen/AwaitingCutover` control committed in one host
    transaction in staging → durable no-overwrite install under the
    namespace lock (an abort that fenced meanwhile wins; staging is
    removed as scratch) → `ReadyToSwitch{activation_ref, applied}`. Still
    frozen. Failure after freeze leaves the source frozen; no timer thaws.
  - `activate_target` holds the same namespace lock activation/abort race
    on, refuses tombstone/absent/wrong-genesis/foreign-op, transitions
    Frozen→Active with the one-time `Activation` marker in the SAME
    control commit; matching retries return recorded evidence + CURRENT
    access mode without mutation.
  - `abort`/`fence_target` fence FIRST (terminal `delete` of a published
    unactivated matching target — `ActivationWon` if activation won — or
    the durable pre-genesis tombstone under the lock), THEN thaw exactly
    the matching frozen source; retries are evidence-only
    (`AlreadyFenced`, `thawed: false`).
  - `initialize` executes the generated chain from the declared EMPTY base
    (seeds actually run, exactly once), records one `Applied` with
    `AppliedSource::EmptyBase`, publishes Frozen/AwaitingCutover; there is
    NO empty-latest-schema entrypoint that could mark skipped seeds
