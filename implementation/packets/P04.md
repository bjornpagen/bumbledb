### P04R resume changes (2026-09-05)

1. **`history/decision.rs` — `blank_initial_digests()` C12 defect FIXED**
   (P05.md defect 2): now returns
   `(codec::empty_application_digest(), codec::empty_system_digest())` — the
   canonical empty export projection under
   `bumbledb.checkpoint.v1/application-digest|system-digest`. The old
   `bumbledb.decision.v1/empty-*` domains are gone. P05's forcing test
   `lane_checkpoint.rs::blank_initial_digests_equal_the_empty_export_projection`
   is now green by construction (NotRun).
2. **`writer/hosted.rs` — composed head bodies + staging epoch + TailPolicy**
   (P05.md defect 3, applied in full):
   - `create` publishes `manifest::genesis_head_body(&authority, object_epoch,
     cap)`; every read path decodes the full `manifest::HeadRecord`
     (`decode_head`) instead of the bare control projection.
   - Decision objects are staged via `store::put_verified(..,
     parent.object_epoch, ObjectKind::Decision, ..)` — the PARENT head's
     `object_epoch`, read per attempt, never the constructor-time constant
     (the GC reference-introduction rule; a post-barrier decision must live
     in the open epoch). The struct's `object_epoch` field is deleted;
     `create` still takes the initial epoch for the genesis head, and
     **`open` no longer takes an epoch parameter** (it reads the head).
   - `attempt_publish` composes the successor with
     `manifest::decided_head_body(parent_body, &candidate.new_authority,
     decision_len, &self.tail_policy, cap)`; `HeadError::MaintenanceRequired`
     maps to the new `LogError::MaintenanceRequired { count, bytes }`.
   - New `tail_policy: TailPolicy` field (default `UNBOUNDED`) +
     `with_tail_policy` builder; `try_submit` consults
     `checkpointer::admission_headroom(&recovery, &tail_policy)` AFTER
     retained-receipt dedup and BEFORE judging — a retained receipt still
     resolves under backpressure; new decisions (no-ops/rejections included)
     refuse `NotSubmitted(MaintenanceRequired)` with nothing dispatched.
   - `catch_up` fetches decisions through `store::fetch_decision` over the
     bounded epoch window `[recovery.epoch_floor, head.object_epoch]`; a walk
     that reaches the recovery root's checkpoint base without meeting the
     local stamp returns the new typed `LogError::MaterializationStale`
     (warm cache older than the tail — recovery hydration required, never an
     empty fallback or fake corruption); absence INSIDE the protected window
     stays `Corruption`.
   - `resolve_after_unknown` now maps a malformed head to `Unknown`, not
     `NotSubmitted` (work had been dispatched; the old `?` conversion was a
     latent certainty bug).
   - Machine bound tightened: `B: ConditionalStore, B::Error: BackendError`
     (satisfied by all P05 adapters and the production MemStore double).
3. **`writer/mod.rs`**: `LogError::{MaintenanceRequired{count,bytes},
   MaterializationStale}` + docs; `impl From<manifest::HeadError> for
   LogError`. `identities.rs`: rows `maintenanceRequired`,
   `materializationStale` appended to the `logError` family (compile-locked).
4. **`writer/decide.rs` — canonical Violations codec CONSUMED** (was the
   bounded `format!("{violations}")` Display placeholder): rejection evidence
   is now `bumbledb::schema::evidence::encode_violations(schema, &violations,
   limits.evidence_bytes, work)` — P01R's landed core codec (family
   `bumbledb.evidence.v1\0`, layout 1): complete violated-statement set,
   deterministic uniform-rank example truncation, exact untruncated u128
   measures, canonical-row example bytes. `EvidenceError::Work` maps to
   `LogError::Work`; every other arm (Budget/Row/impossible shapes) maps to
   `IncompleteRejectionEvidence` — a nonterminal refusal before deciding
   (chapter 20), never a shorter recorded verdict. Historical replay
   (`apply.rs`) re-derives byte-identical evidence since the codec is a pure
   function of (schema, violations, budget).
5. **`writer/decide.rs` — borrowck restructure** (the recorded
   `judge_and_seal` nested-reborrow compile risk was REAL): with
   `WriterSession::prepare<'owner>(&'owner mut self) ->
   Admission<PreparedWrite<'owner,..>>` and a single
   `judge_and_seal(&'owner mut session) -> Candidate<'owner>` function, the
   accepted arm's escaping `PreparedWrite` pins the first `prepare` reborrow
   to the universal `'owner` region, so the rejected arm's second
   `prepare(empty)` is a conflicting mutable borrow on stable NLL (problem
   case #3). `judge_and_seal` is replaced by `prepare_real` /
   `prepare_empty` / `seal_candidate` (+ pub(crate) `Judged`), called where
   the session is a LOCAL (local.rs `try_submit`, hosted.rs
   `attempt_publish`, apply.rs `materialize`) so every borrow region stays
   existential and the rejected arm legally re-prepares. No double
   judgment, no unsafe, identical semantics (empty replacement delta sealed
   in the same exclusive session after a rejection/failed precondition).
6. **`writer/verbs.rs`**: blanket `ConditionalStore` impls for `&T` and
   `Arc<T>` (all verbs take `&self`) — one adapter instance can serve the
   publication machine, checkpointer and collector concurrently.
7. **`history/types.rs`**: `RejectionEvidence` doc now names the landed core
   codec module/family.
8. **Tests updated**: `tests/writer_hosted.rs` REWRITTEN onto the production

### P04R2 closure changes (wave D, 2026-09-05)

1. **`writer/hosted.rs` — public read-side catch-up verb** (P06R2 hub
   request 6 / P06.md defect 4): `pub fn HostedHistory::catch_up(&self,
   work) -> Result<DecisionStamp, LogError>` — reads the current composed
   head and advances the LOCAL materialization to its tip through the SAME
   bounded decision-window walk `submit`/`resolve` use (the private walker is
   renamed `catch_up_to(&HeadRecord, ..)`; no second machinery). Returns the
   reached tip stamp so a hosted snapshot with `consistency: latest` can pin
   a generation at/after it. It performs NO head write: a missing head is
   `NotInitialized` (never initializes), a tombstone head is
   `DatabaseDeleted` (never transitions anything), and a warm cache older
   than the checkpoint base still reports `MaterializationStale` for the
   recovery lane — never an empty fallback.
2. **`writer/hosted.rs` — per-call submit bounds** (P04R concern 5 / P06.md
   defect 8): new `SubmitOptions { attempts: Option<u32>, backoff_base:
   Option<Duration>, backoff_cap: Option<Duration> }` (+ `DEFAULT`) and
   `pub fn submit_with(&self, command, options, work) -> SubmitOutcome`
   (`submit` delegates with defaults; `try_submit` takes the options). The
   options tune ONE call and never consume/reconfigure the machine
   (`with_attempts` still exists for construction-time configuration). They
   CANNOT exceed the machine's own bounds: per-call attempts clamp to
   `1..=configured attempts` (`effective_attempts`; zero still makes one
   attempt — a submit never fabricates NotSubmitted without dispatching),
   and every backoff delay (`base * 2^n`, per-loss exponential) clamps to
   both the per-call cap and the new machine bound `MAX_BACKOFF` (5s), so a
   hostile wire value cannot park an owning worker. Backoff sleeps ONLY
   after a definite CAS loss (`AttemptResult::Lost`, candidate dropped,
   nothing published) and never after the final attempt; unknown outcomes
   resolve immediately; the loop-top `work.checkpoint()` still bounds the
   deadline after any sleep.
3. **`writer/mod.rs`**: re-exports `SubmitOptions` beside `HostedHistory`.
4. **`identities.rs` — NO change needed (decision recorded)**: P04R2 adds no
   enum variant to any compile-locked family (`SubmitOptions` is parameter
   data, not a boundary refusal/outcome kind; the catch-up verb reuses the
   existing `LogError` rows). The wave-C golden-regeneration obligation is
   unchanged.
5. **P09 seam CLOSED in their file under this closure's ownership**
   (`migration/hosted.rs` — hub request 2 below is now APPLIED, recorded in
   P09.md): the hosted migration cutover reads/writes composed
   `manifest::HeadRecord` frames exactly as `writer/hosted.rs` does.

## Implemented behavior

- LocalHistory: unchanged semantics (facts + retained receipt + control
  attachment in one core LMDB transaction; four durable terminal outcomes;
  receipt-lookup dedup; ABA-detecting exact-state witness; deleted authority
  refuses before any receipt answer).
- HostedHistory: prepare private candidate against the captured COMPOSED head
  → headroom consult → upload the one immutable decision object under the
  parent head's open epoch (verified content-addressed put) → conditional
  HEAD replace with the composed successor body (retention preserved, tail
  accounting grown, envelope enforced) → commit local. CAS loss re-evaluates
  the same command against the winner (bounded). Unknown CAS/upload resolves
  by catch-up materialization + retained receipt, else `OutcomeUnknown`.
  Catch-up walks the bounded epoch window and distinguishes stale-cache
  (`MaterializationStale`) from retention violation (`Corruption`).
- Rejection evidence: the core's canonical `bumbledb.evidence.v1` bytes,
  complete-or-refused, deterministic under replay; framed verbatim into
  decisions and retained receipts.
- `apply::materialize`: unchanged verification semantics over the new decide
  API (re-decodes the embedded command, re-judges at the exact predecessor,
  requires byte-exact outcome/evidence and digest agreement).
