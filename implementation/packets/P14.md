## Decisions of record

1. **NOSYNC lane: dropped, not re-homed (ENG-008).** P02 deleted the whole
   `*_nosync` constructor surface. A bench-owned MDB_NOSYNC would have to
   fork the store's environment owner (measuring a fake engine, not this
   one), and an unpaired SQLite `synchronous=OFF` twin against a syncing
   engine violates chapter 40's fairness rule — so the weakened ours lane
   AND its OFF mirror are gone. `StoreMode`/`DurabilityLane` survive as
   single-variant (`Durable`) seams because P11-owned lanes thread them in
   signatures. The retired CLI spellings (`--nosync`, `--ephemeral`,
   `--lanes nosync`, churn run `nosync`) refuse loudly, naming ENG-008 —
   never a silent durable fallback. Decision text also lives in
   `storemode.rs`/`duralane.rs` docs.
2. **Application-owned ids (E-NO-RESERVE).** Every `tx.reserve`/
   `reserve_at`/`fresh_field` call in the bench is replaced by bench-owned
   cursors: `writebench::PostingMint` (MAX(id)+1 probed from the live store
   per family entry — the exact mint the SQLite twin always used, probed in
   untimed setup), `churn::OursLane::last_minted` (cursor advances only on a
   committed cycle — replay-exact, monotone by construction, no burn),
   crud's `MintCursor` (renamed from `FreshCursor`; the cursor IS the id
   authority now), disjoint high mint bases for the windowed/capacity
   commit families (`MINT_BASE` consts; per-family persistent cursors so
   traced re-runs keep inserting NEW rows instead of degrading into no-op
   duplicate commits), and dense index-aligned generator ids in primerlane.
3. **Schema `fresh` markers → declared id keys, placed FIRST in each
   declared list.** Successor materialized order is closed auto-handle keys
   then declared statements; putting the id keys at the declared head makes
   the pre-declared statement count equal the old fresh+closed auto count,
   so EVERY later declared statement id keeps its historical position
   (verified against the sqlmap DDL goldens, which come out unchanged, and
   the querygen/target pins s24..s31, untouched).
4. **`fact_hash` model → 16-byte fingerprint model.** `sweep.rs`'s
   `model_fact_hash` (32-byte `Digest`) became `model_fact_fingerprint`
   (first 16 bytes of `derive_key`-domain BLAKE3, domain string mirroring
   P01's private constant, same convention as hashprobe's
   `FINGERPRINT_PROBE_CONTEXT`); `pin_hash_model` still convicts any
   model/engine drift at runtime before a sweep number is trusted.
5. **Intern dictionary paths purged (ENG-006).** `driver/verify_store.rs`
   no longer renders the dangling-intern-ids leak line and no longer names
   `CorruptionError::FreshRowDeterminantEntry`.
